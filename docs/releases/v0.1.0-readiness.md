# v0.1.0 source-release readiness

Status: qualification in progress, October 10, 2026. This record does not
approve publication or claim general production readiness.

## Release contents

The release tags the repository as `v0.1.0` and publishes GitHub source
archives and release notes. It includes the CLI, server, device collector,
MCP server, harness plugins, admin console, and deployment sources. It does
not publish built binaries or container images, or upgrade a deployment.
The source-release workflow verifies the tag after publication; a failed
verification does not retract the release.

The owner-selected collection, folder-policy, coverage, and bounded
opt-in two-worker work is complete. Runtime code deployed at `7cc9fd9`
matches the candidate tested at `f6f4530`; subsequent differences are tests,
documentation, and release metadata. Defaults remain one upload worker.

## Local index and retrieval results

The full index processed 15,569 sources and 22.97 GB of parser input. It stored
1,961,257 messages in 15,734 conversations, with all 5,920 parent links
resolved. Measured index wall time was 12m31s; the database was 2,775,138,304
bytes after checkpoint. Staging has four CPUs and 4 GiB RAM. These measurements are not comparable to the
optional reference-laptop acceptance baseline.

Local retrieval passed its configured literal, regular-expression, and
full-text query checks. The slowest observed queries were 301.063 ms for
literal grep, 488.592 ms for regular-expression grep, and 237.945 ms for
full-text search. No general latency guarantee is inferred.

Append latency passed over 20 appends to one copied Claude transcript:
p50 63 ms, p95 69 ms, maximum 82 ms. Placement processed 15,568 Claude/Codex
transcripts: 13,453 placed by cwd, 2,030 by folder, and 85 by remote. No original
Mac checkout directory was present in the staging filesystem.

## Chunking results

The full Claude/Codex dry run processed 23,439 files and 21.99 GB with zero
errors. It sent 21,252.8 MB of unique uncompressed finalized chunks as
7,876.7 MB on the wire, a 2.70 compression ratio. The run took 7m43.780s and
left zero spool bytes. Its in-memory server validates chunk handling; it does
not replace the real PostgreSQL/MinIO ingest checks.

Codex replay passed through 11,918 syncer requests. Payload totaled 219.1 MB
for a 212.6 MB transcript, a 1.03 upload ratio. The test verified that the
server's finalized chunks and final tail covered the full copied file.

## Corpus gate scope

The full local-index check includes Claude, Codex, and the Devin SQLite store.
Placement and chunking/replay checks cover Claude and Codex; append latency
uses one copied Claude transcript. Ingest and server retrieval use the recent
Claude/Codex window plus every Devin session, not a time-limited Devin sample.

The copied corpus runs on Linux staging. Original Mac working directories and
repositories are absent, so placement observations do not qualify repository
resolution on the native Mac filesystem. The staging shell is not a live
harness session; actual MCP self-exclusion is covered by the separate fresh
Claude and Codex sessions above. Optional laptop acceptance benchmarks and
external-oracle comparisons were not run.

## Two-Mac recovery test

Two real Macs ran temporary collectors with separate configuration, roots,
indexes, sockets, and pinned authenticated connections to a private staging
server. The production server and live device configurations stayed in use.
Each temporary collector had one synthetic Claude source. The initial markers
were searchable locally and across the two Macs.

The test server was held stopped for at least 60.021 seconds before restart.
Both Macs collected an append during that interval without hooks. After the
first observed readiness response, shared search found the M5P append within
9.120 seconds and the first-Mac append within 10.601 seconds. Each marker had
one matching hit in its expected session. Exact shared reads verified the two
initial and two offline markers; these final reads ran from the first Mac.

An earlier rehearsal stopped correctly but could not restart its transient
service. Its evidence remains separate. The successful run used a restartable
test service and new markers. Independent review confirmed the timing and
content checks. Temporary collectors, tunnels, and the test server were
stopped after verification.

This checks synthetic native records on two machines, not every provider,
actual harness generation, or a general catch-up latency guarantee. The
copied-history Docker check remains a separate gate.
