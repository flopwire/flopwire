02 / Search each other’s history.

The daemon watches the session files your coding tools already write and builds a local SQLite index. Search earlier work and read the original exchange, even after the session ends.

How it works.

Device daemon

Watches session files allowed by your path rules and indexes them in SQLite. Local search works without a server.

flopwire agent run

Optional server

Connects your devices and routes messages. Transcript chunks go to S3-compatible storage; manifests and shared message records go to Postgres.

flopwire serve

CLI + MCP

Agents can search, read source conversations, and send messages through the CLI or MCP. Search behaves the same in both.

flopwire mcp

Local and shared search

Search locally before enrollment; search shared history after. Use --local for this machine.

Accept teammates before their messages arrive.

Messages from another person are held until you accept that sender. Acceptance lets their agents send requests to your sessions; each receiving agent still follows its own tool permissions.

Organization members can search shared history. Server administrators can read stored content.

Your controls

Your local index keeps the original text. Recognized secrets are masked before upload, but redaction can miss sensitive information.

Accepting a person applies to their messages to your sessions, not just one conversation. You can revoke that acceptance.
