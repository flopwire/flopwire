# Hook context caps and hook cost, 2026-10-03

Measurements for #68 (plan section 8): how much hook `additionalContext`
each harness passes to the model, what it does past that, what the message
wrapper costs in tokens, and how long `flopwire hook` takes on
`PostToolUse`. They set `busproto.MaxBodyBytes`, `busrender.HookBytes`,
`busrender.HookMessages` and `hookPendingBudget`.

Versions: Claude Code 2.1.288, codex-cli 0.160.0, Devin CLI 3000.11.1.
Machine: Apple M1 Pro, 10 cores, macOS 26.2.

## Method

The marker method of [`probes-2026-10-01.md`](probes-2026-10-01.md). A
probe hook (Python) printed `additionalContext` of exactly N characters
on one event, once per run: a line `BEGIN-<tag>`, numbered lines
`M0000001 lorem ipsum …` (64 bytes each), a line `MIDDLE-<tag>` at the
half, dots, and `END-<tag>` as the last bytes. The tag was 8 random hex
digits per run. The prompt asked the model, without tools, for the BEGIN,
MIDDLE and END tokens and the highest M number it saw. For
`PostToolUse` the prompt first asked for `echo probe`. The harness's own
record was then read: the Claude transcript, the Codex rollout, the Devin
`sessions.db` (read-only).

Every run used a scratch project under the session scratch directory and
project-scope hooks only. No user harness config was read or changed:

- Claude Code: `.claude/settings.json` in the scratch project;
  `env -i HOME USER LANG TERM=dumb PATH=… claude -p --model haiku --setting-sources project --output-format json --allowedTools 'Bash(echo:*)'`.
- Codex: an isolated `CODEX_HOME` holding a copy of `auth.json` (mode 600)
  and a `hooks.json`; `codex exec --json -m gpt-5.6-luna -c model_reasoning_effort=low --dangerously-bypass-hook-trust -s read-only --skip-git-repo-check -`.
  The `auth.json` copy had the same checksum at the end (no token
  refresh) and was deleted after the runs.
- Devin: `.devin/hooks.v1.json` in the scratch project;
  `devin -p --model swe-2-medium --permission-mode smart --respect-workspace-trust false`.

Runs: 16 Claude (Haiku, $0.25 in total), 15 Codex, 9 Devin.

## 1. Context size per harness

N is the length of `additionalContext` (ASCII, so characters = bytes,
except the € rows). "Intact" means the model quoted BEGIN, MIDDLE and END
and the last M number, and the stored record held all N.

| Harness | Event | N | Model saw | Stored |
|---|---|---|---|---|
| Claude Code | UserPromptSubmit | 4,000; 9,500; 10,000 | intact | inline |
| Claude Code | UserPromptSubmit | 9,500 characters of € (25,683 bytes) | intact | inline |
| Claude Code | UserPromptSubmit | 10,001; 10,500; 16,000; 65,536; 1,048,576 | BEGIN, M1–M31 only | `<persisted-output>` file reference and "Preview (first 2KB)" |
| Claude Code | PostToolUse | 4,000; 10,000 | intact | inline |
| Claude Code | PostToolUse | 10,001; 262,144 | BEGIN, M1–M31 only | file reference and 2 KB preview |
| Codex | UserPromptSubmit | 4,000; 10,000 | intact | 10,000 bytes, whole |
| Codex | UserPromptSubmit | 10,001; 16,384; 65,536; 262,144; 1,048,576 | BEGIN and END, no MIDDLE | about 10,100 bytes: head and tail, middle replaced |
| Codex | UserPromptSubmit | 5,000 characters of € (13,524 bytes) | BEGIN and END, no MIDDLE | truncated, as above |
| Codex | PostToolUse | 4,000; 10,000 | intact | whole |
| Codex | PostToolUse | 10,001; 1,048,576 | BEGIN and END, no MIDDLE | truncated, as above |
| Devin | UserPromptSubmit | 4,000; 10,001; 16,384; 65,536; 262,144; 1,048,576 | intact | whole (`role: "system"`) |
| Devin | PostToolUse | 4,000; 65,536; 1,048,576 | intact | whole |

The limits:

- **Claude Code: 10,000 characters**, on both events. 10,000 arrives
  inline; 10,001 does not. The count is characters, not bytes: 25,683
  bytes of € (9,733 characters) arrived inline. Past the limit the
  context is written to
  `~/.claude/projects/<project>/<session>/tool-results/hook-<id>-additionalContext.txt`
  (all N bytes, also at 1 MiB) and the model gets a `<persisted-output>`
  block: "Output too large (10.3KB). Full output saved to: <path>", then
  the first 2 KB. The model can read the file with a tool; Haiku did not
  unless asked.
- **Codex: 10,000 bytes**, on both events. Past it, Codex keeps about
  10,000 bytes, the head and the tail, and replaces the middle with
  `…N tokens truncated…`. It prepends `Warning: truncated output (original
  token count: T)` and `Total output lines: L`, and appends `Full hook
  output saved to: $TMPDIR/hook_outputs/<thread>/<uuid>.txt`. T is
  bytes / 4, rounded up (10,001 bytes: 2,501). The count is bytes: 5,000
  € characters (13,524 bytes) were cut.
- **Devin: no limit seen up to 1 MiB**, on both events. The 1 MiB
  context is stored whole in `message_nodes`.

Past the limit, no harness drops the context, reports an error, or kills
the hook. None logs anything: Claude Code's stderr was empty, the Codex
`logs_2.sqlite` has no hook or truncation entry, and the Devin log has
none. The only signal is in the model's context (Claude's
`<persisted-output>`, Codex's warning line).

## 2. Wrapper cost

One request message as `flopwire hook` prints it (agent from this branch,
local mode): body "Can you rebase api on main before 3pm UTC?" (42 bytes).
The whole `additionalContext` is 476 bytes, so the wrapper is 434 bytes:
209 for the `<flopwire-message>` tag and its attributes, 225 for the reply
line. An `inform` message has no reply line. The standing instruction is
1,286 bytes (EncodedLen).

Input tokens with the same prompt and three contexts, consecutive runs:

| Harness | No context | Body only | Wrapped message | Wrapper |
|---|---|---|---|---|
| Claude Code (Haiku), input + cache tokens | 21,986 | 22,019 | 22,224 | 205 |
| Codex (gpt-5.6-luna), `input_tokens` | 14,766 | 14,783 | 14,972 | 189 |

Devin `-p` reports no token usage. Its context is the same raw text.
Filler text ran at about 3.9 bytes per token on Claude (4,000 bytes: 1,023
tokens).

## 3. Hook latency

`flopwire hook` from this branch, against a device agent run in the
scratch directory (`agent run --no-sync`, empty Claude and Codex homes,
`--devin-db -`) and two synthetic sessions. Each call was a fresh process
fed a `PostToolUse` input, timed from spawn to exit by Python. The
recipient's inbox was empty and its standing instruction already
delivered, so the hook printed nothing. "sh" runs the plugin's command
line, `/bin/sh -c "flopwire hook || true"`. The binary is 40 MB.

The machine was busy: other agents were running `go test -race` and a VM,
at load averages of 30 to 100 on 10 cores. `/usr/bin/true`, timed the
same way, is the floor.

| Case | Load (1 min) | n | Median ms | p95 | p99 | Max | Over 200 ms |
|---|---|---|---|---|---|---|---|
| `/usr/bin/true` | 37 | 200 | 4.7 | 45.4 | 83.1 | 104.6 | 0 |
| warm, direct | 37 | 500 | 33.1 | 95.6 | 175.5 | 488.7 | 3 (0.6%) |
| warm, sh | 37 | 500 | 50.8 | 106.2 | 136.4 | 257.3 | 1 (0.2%) |
| warm, one message delivered and confirmed | 40 | 25 | 67.0 | 185.9 | — | 342.0 | 1 |
| pending request alone (dial, ask, answer) | 40 | 1,000 | 0.5 | 4.4 | 19.4 | 114.8 | 0 |
| cold (no agent), direct | 60–100 | 300 | 140.8 | 673.7 | 1,192 | 2,389 | 125 |
| interleaved: `true` | 69–103 | 400 | 5.7 | 66.9 | 122.8 | 202.4 | 1 |
| interleaved: warm, direct | 69–103 | 400 | 151.8 | 789.6 | 1,418.9 | 1,804.9 | 177 |
| interleaved: cold, direct | 69–103 | 400 | 98.1 | 832.2 | 1,202.6 | 1,355.2 | 147 |
| interleaved: warm, sh | 69–103 | 400 | 179.4 | 1,084.1 | 1,501.5 | 1,683.5 | 186 |

A rerun waited 40 minutes for the load to fall under 12 and was
dropped: it stayed between 38 and 110.

Reading:

- The 200 ms budget bounds the pending request, not the process. That
  request took 0.5 ms median and 115 ms at most in 1,000 calls at load 40.
  None ran out. In the 1,000 warm calls at load 37 no hook wrote to
  stderr, so none reported a timeout. In the interleaved run at load
  70–100, 2 of 400 warm calls wrote to stderr; the text was not kept.
- The wall time is process start. At load 37 the warm hook added 33 ms
  median (51 ms through `sh`), close to the 20 ms #99 measured on a quiet
  machine, with 0.2–0.6% of calls over 200 ms. At load 70–100 every
  process start slows: the warm hook's median went to 150 ms and its p95
  to 0.8 s, and cold was no faster. Nothing in the hook path can fix
  that; `hookLate` (3 s) is what stops a hook that started that late
  from leasing.
- Cold (no agent): the dial fails at once and the hook prints "the device
  agent is not running; nothing delivered" on stderr. Under the same load
  it cost about the same as warm, so a stopped agent does not slow tool
  calls.

## 4. Decisions

- **`busrender.HookBytes` stays 9,000.** The binding limits are Claude
  Code's 10,000 characters and Codex's 10,000 bytes, on both events.
  `EncodedLen` is never below either count, so 9,000 keeps 10% under both
  for harness drift. Devin needs no lower cap. Past the limit Claude
  hides all but 2 KB and Codex hides the middle, so a hook call must
  never go over: the cap is per hook call, never per message.
- **`busproto.MaxBodyBytes` stays 4,000.** A 4,000-byte body (about 1,000
  tokens), its usual 434-byte wrapper and the 1,286-byte standing
  instruction come to about 5,700, inside one hook call. The largest
  possible frame (4,000, every attribute and ref at its cap) leaves 3,710
  for the body next to the instruction; a body past that is cut with a
  pointer to `flopwire inbox` (unchanged). Raising the cap would only
  move more messages onto that path.
- **`busrender.HookMessages` stays 5.** The byte cap already limits long
  messages to one or two per call. For short ones, five at about 200
  tokens of wrapper each plus bodies is about 1,500 tokens on one tool
  result, which is acceptable; more would mainly add wrapper tokens.
- **`hookPendingBudget` stays 200 ms.** The request's worst case was 115
  ms at load 40, so 200 ms leaves margin without letting a wedged agent
  add more than 0.2 s to a tool call.

No value changed. The comments on the four constants now cite this note.

## Not measured

- Interactive sessions. The hooks are documented to behave the same.
- `SessionStart` context size (it prints the standing instruction and the
  same messages through the same cap).
- Devin past 1 MiB, and its token cost.
- Hook latency on a quiet machine in this session. #99 measured about
  20 ms there.
